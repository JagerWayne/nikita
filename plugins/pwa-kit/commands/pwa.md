## 2. Libraries: latest, pinned, vendored
For each library: look up the **real latest stable** (`npm view <pkg> version` + release notes; never memory, no pre-releases), compare, upgrade, fix breaking changes (e.g. three.js: ES modules via importmap, no removed `examples/js`). Download into `vendor/<name>-<exact-version>/` (version in the folder name, so a new version is a new URL and cache-first can never serve an old copy), keep the licence, list every file in `APP_FILES`, write `vendor/README.md` (library, version, source, licence), copy `check-deps.mjs` to `tools/`. No runtime CDN links, no `@latest`. After upgrading run the app and fail on console errors/deprecation warnings; if an upgrade can't be made to work, keep the old version and report why.

## 3. Service worker + update client (use the templates)
Copy `sw.js` to the root (set `PREFIX`), paste `pwa-client.js` into the startup script, add `pwa-ui.html` markup/CSS (restyle to the app), call `refreshOfflineCache()` after the first screen shows. Behaviour that must hold (all already in the templates; keep it when adapting):
- **Install downloads every file in `APP_FILES` with byte progress** (worker posts `{loaded,total,...}`, throttled, with a trailing update so the last value is never dropped), and **throws if any file failed**, so a half-downloaded version is never installed and the old one keeps running.
- **No `skipWaiting()` on install.** A worker whose version equals the running page's swaps in **silently with no reload** (the page already is the new version); a newer one waits for the player ("NEW VERSION - TAP TO UPDATE", shown only on the menu, never mid-game). Only a user-initiated update reloads on `controllerchange`.
- **Check for updates** compares the server's `version.js` (cache-busted) with `APP_VERSION`, because `reg.update()` alone never finds a release (the version is in the worker URL). On a newer version it calls `installVersion(latest)`: registers `sw.js?v=<latest>`, shows the progress bar, switches, reloads. States: Checking, Up to date (vX), Update available, Offline, Error.
- **Progress bar UI:** percentage and bytes ("42% (1.2 MB / 2.9 MB)"), modal over the whole app for updates (also when started from the banner or a silent check), small non-blocking strip on the first visit ("Downloading for offline play"). Never goes backwards, 100% only when finished; failure hides it, keeps the old version and shows Retry.
- Page = network-first, own css/js network-first + revalidated, everything else cache-first; old caches (same prefix) deleted on activate.
- Offline badge, `navigator.storage.persist()` after the first tap, all storage/cache calls in `try/catch`, silent update check on start and on returning to the foreground (max every 30 min).

## 4. Install button
Hidden unless the browser fires `beforeinstallprompt` (Chrome/Edge/Android); hide on `appinstalled` and when already standalone. iOS Safari never fires it: show "Tap Share, then Add to Home Screen" when iOS (also iPadOS: `MacIntel` + `maxTouchPoints > 1`) and not standalone. If the app has an existing install button with manual instructions, keep it.

## 5. Title screen and menu (skip with `--no-title`; restyle an existing title screen instead of adding a second one)
First screen shows the **icon, game name and version** (from `APP_VERSION`) and a menu of large touch-friendly buttons (>= 48 px, arrow keys + Enter, visible focus, safe-area padding, works in landscape phone size 844x390 and desktop):

| Button | Behaviour |
|---|---|
| **New** | Starts fresh and **deletes the old save**. If a save exists, an in-app confirm dialog first (never `window.confirm`). Deletes only the app's own keys; keeps preferences. |
| **Continue** | Resumes from storage. Disabled when there is no valid save; validates the data (corrupt save: tell the player, never crash), migrates old formats. Show where you'd resume. |
| **Options** | Options menu (volume, controls, quality, Check for updates, Install, Delete save data, About/version, whatever the app really has). **Hide the button if the app has no options.** |
| **Exit** | Autosave, stop audio/animation loops/timers, `window.close()`; if still open after ~300 ms (browser tab, iOS) show "Thanks for playing / you can now close the app" with a **Back to menu** button. Browsers can't truly quit; never leave a dead screen. |

Default focus: Continue when a save exists, else New. Escape / Android back returns to the menu or pauses (`history.pushState` + `popstate`), after autosaving. If the game has no mid-game save, define Continue as "resume the saved campaign (progress, credits, upgrades, last level)" and record the resume point when a level starts.
**Delete save data** (in Options, red, in-app confirm with Cancel focused): removes the app's keys (a `SAVE_KEYS` list in one place, never `localStorage.clear()`: other apps share the `github.io` origin), IndexedDB databases it created, resets in-memory state, reloads. It must **not** unregister the worker or delete the offline cache. Optional: Export/Import save as `.json` (validate before applying).
**Landscape-only games:** manifest `orientation: landscape`; after the first tap try `requestFullscreen()` then `screen.orientation.lock('landscape')` (try/catch; iOS ignores it); always keep a full-screen "Rotate your device" overlay for portrait that pauses the game and resumes when rotated. Don't rotate the canvas with CSS unless asked.

## 6. Docs and release flow
README gets "Install" and "Releasing": 1. change files; 2. add new files to `js/boot/files.js`, run `node tools/make-sizes.mjs` and `node tools/check-deps.mjs`; 3. bump `APP_VERSION`; 4. push (Pages deploys in ~1 minute). Never bump a cache name by hand.
